# 要件定義書

## 概要

電子部品製品の在庫管理を行うREST APIシステム。Java Spring BootとMariaDBを使用して、電子部品の登録、更新、削除、検索、在庫数量の管理を提供する。

## 用語集

- **電子部品管理システム**: 電子部品の在庫情報を管理するWebAPIシステム
- **電子部品**: 抵抗、コンデンサ、IC等の電子回路で使用される部品
- **在庫数量**: 現在保管されている部品の個数
- **部品カテゴリ**: 部品を分類するためのグループ（抵抗、コンデンサ、IC等）
- **部品コード**: 各部品を一意に識別するためのコード
- **在庫閾値**: 在庫が少なくなった際に警告を出すための基準値
- **データベーススキーマ**: 別チームが設計・作成するテーブル定義とDDL

## 要件

### 要件1

**ユーザーストーリー:** 在庫管理者として、新しい電子部品を登録したい。そうすることで、システムで部品を管理できるようになる。

#### 受入基準

1. 電子部品管理システムは、部品名、部品コード、カテゴリ、仕様、単価、在庫数量を含む部品情報を保存しなければならない
2. 電子部品管理システムは、部品コードが重複する場合、エラーメッセージを返さなければならない
3. 電子部品管理システムは、必須項目が未入力の場合、バリデーションエラーを返さなければならない
4. 電子部品管理システムは、部品登録が成功した場合、201ステータスコードと登録された部品情報を返さなければならない

### 要件2

**ユーザーストーリー:** 在庫管理者として、既存の電子部品情報を更新したい。そうすることで、部品の仕様変更や価格変更に対応できる。

#### 受入基準

1. 電子部品管理システムは、指定された部品コードの部品情報を更新しなければならない
2. 電子部品管理システムは、存在しない部品コードが指定された場合、404エラーを返さなければならない
3. 電子部品管理システムは、更新が成功した場合、200ステータスコードと更新された部品情報を返さなければならない
4. 電子部品管理システムは、部品コードの変更を許可してはならない

### 要件3

**ユーザーストーリー:** 在庫管理者として、不要になった電子部品を削除したい。そうすることで、システムを整理できる。

#### 受入基準

1. 電子部品管理システムは、指定された部品コードの部品を削除しなければならない
2. 電子部品管理システムは、存在しない部品コードが指定された場合、404エラーを返さなければならない
3. 電子部品管理システムは、削除が成功した場合、204ステータスコードを返さなければならない

### 要件4

**ユーザーストーリー:** 在庫管理者として、電子部品を検索したい。そうすることで、必要な部品を素早く見つけることができる。

#### 受入基準

1. 電子部品管理システムは、部品名での部分一致検索を提供しなければならない
2. 電子部品管理システムは、カテゴリでの絞り込み検索を提供しなければならない
3. 電子部品管理システムは、在庫数量での範囲検索を提供しなければならない
4. 電子部品管理システムは、検索結果をページネーション形式で返さなければならない
5. 電子部品管理システムは、検索条件に一致する部品が存在しない場合、空のリストを返さなければならない

### 要件5

**ユーザーストーリー:** 在庫管理者として、部品の在庫数量を調整したい。そうすることで、入荷や出荷に対応できる。

#### 受入基準

1. 電子部品管理システムは、指定された部品コードの在庫数量を増加させなければならない
2. 電子部品管理システムは、指定された部品コードの在庫数量を減少させなければならない
3. 電子部品管理システムは、在庫数量がマイナスになる場合、エラーメッセージを返さなければならない
4. 電子部品管理システムは、在庫調整が成功した場合、200ステータスコードと更新された在庫情報を返さなければならない
5. 電子部品管理システムは、存在しない部品コードが指定された場合、404エラーを返さなければならない

### 要件6

**ユーザーストーリー:** 在庫管理者として、在庫が少ない部品を確認したい。そうすることで、発注のタイミングを把握できる。

#### 受入基準

1. 電子部品管理システムは、在庫数量が指定された閾値以下の部品リストを返さなければならない
2. 電子部品管理システムは、低在庫部品リストを在庫数量の昇順で返さなければならない
3. 電子部品管理システムは、低在庫部品が存在しない場合、空のリストを返さなければならない

### 要件7

**ユーザーストーリー:** システム管理者として、APIのエラーハンドリングが適切に行われることを確認したい。そうすることで、システムの信頼性を保てる。

#### 受入基準

1. 電子部品管理システムは、不正なリクエスト形式の場合、400エラーと詳細なエラーメッセージを返さなければならない
2. 電子部品管理システムは、データベース接続エラーの場合、500エラーを返さなければならない
3. 電子部品管理システムは、すべてのエラーレスポンスに統一されたエラー形式を使用しなければならない
4. 電子部品管理システムは、エラー発生時にログを出力しなければならない
